# Working on this repository

Fast feedback: `pytest -q` (about a minute, builds a small world once), `ruff check src tests`,
`mypy src`, `cd web && npm run check`. Everything: `rdw-sim && rdw report && rdw heldout v1`, then
`cd web && npm run build && npx playwright test` against `RDW_TODAY=2026-10-26 rdw serve`.

Invariants (each has a test or a CI step):
- Only `src/rdw/evaluate.py` reads `data/truth`; `src/rdw` never imports `rdw_sim` (`tests/test_isolation.py`).
- Thresholds, effort cuts, vocabularies and customer profiles live in `config/`, not in code.
- The agents read and rules decide; a person confirms answers in the console. Reviews never change the
  agents' output, only the compliance matrix and the acceptance KPI.
- A projected number is never shown as measured: every KPI carries its basis.
- `reports/WORKBENCH.md` and `reports/workbench.json` are generated by `rdw report`; CI rebuilds and diffs them.
- Held-out sets: never change the agents to pass `heldout/<set>`. Its first run
  (`reports/heldout/<set>/first_run.json`) is never rewritten. If you read a set's failures, write
  `regression` to `heldout/<set>/STATUS` and have someone who has not seen the code write a new set from
  `heldout/WRITING_TENDERS.md` only. The console and MCP server show counts, not sentences.
- Console: colours, sizes and durations come from `web/src/shared/theme/`; every view handles loading,
  error and empty.
